# 多设备同步

沿用现有 Firebase 项目 `daily-calorie-tracker-3ec47` 的匿名认证和 Firestore 服务。Web 配置是客户端公开配置，不包含管理凭证；未修改 Firebase 安全规则，也未创建新云服务。

入口为顶部“☁ 同步”。各设备输入同一个12–24位同步码；建议使用“生成新码”产生20位随机码。连接时合并本机和云端内容；已有云端字段优先，本机独有项目保留。用户明确点击连接后保存同步码，随后自动重连。

- 文档为 `syncSpaces/<SHA256(project-flowline:CODE)的前24位>`，与原综合打卡工具的 `project-suite:` 命名空间分开，不读写其他工具的数据。
- 模板、项目、清单、节点和待办使用稳定 ID；逐字段版本与删除标记合并，不整体覆盖工作空间。排序独立记录，页面选择保留在本机。
- 同时修改不同字段会合并；同一字段用提交时重新标记的较新版本。尚未提交的修改只针对真正改过的字段重标，旧设备未改过的字段不会覆盖新内容。
- 施工图备注按列、行、单元格合并；正在输入、编辑弹窗或拖动时延迟接收界面更新，保存后再合并。
- Payload 压缩后以同步码派生的 AES-GCM 密钥加密，随机 IV。同步码不上传、不放入 URL，不作为静态资源发布。Firestore 中仅保存密文。
- 各次本机保存都会保留待上传修改。断网先写本机，恢复网络后重试。关闭前已经保存的操作会在下次连接时继续发送。
- 收到远端内容前保留最近3份本机恢复备份，可在同步面板导出。接收远端修改后清空旧的整体撤销历史，避免“撤销”误恢复别人已改过的整份旧数据。
- 同步缓存按空间独立保存。更换同步码会将本机当前内容合并到新空间；断开不会删除本机或云端内容。
- 首次空项目占位符不上传。个人 JSON、同步码和测试用临时数据不得提交到仓库。

构建使用固定版本的 Firebase 11.10.0 与 esbuild 0.25.12，输出自托管的 `cloud-sync.js`；只在启用同步时加载。普通脚本格式兼容 Safari 及本地 HTML 打开方式。

`npm test` 验证模型合并、冲突、删除、恢复、加密和已有工作空间功能。

`FLOWLINE_LIVE_TEST=1 node tests/cloud-live.mjs` 可显式运行隔离的双匿名客户端实测，只写随机同步空间中的合成数据，并在结束时删除该临时文档。浏览器验证另使用不同来源的两台隔离客户端。
